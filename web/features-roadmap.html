🏛️ System Architecture & Dynamic Database Decoupling
✅ Implemented

Local-first creator workstation engineered in Python (FastAPI backend + Vanilla JS/CSS UI) running SQLite without external cloud databases.

  • Dynamic DB Path (YLA_DB_PATH): Database can reside at the project root or any external SSD / partition (e.g. D:\YouTubeData\uploader.db). Configurable via .env.
  • Dual-OS Portability: 100% identical codebase and execution across Windows 11 and Ubuntu Linux.
  • RBAC Security: Built-in User Role engine (admin, editor, viewer) with bcrypt hashing and tamper-proof sessions.

⏳ Smart Multi-Platform Cleaner & Archiver
⏳ Planned

Sync-verified storage staging tool where deletions NEVER happen automatically. Files are staged only after 100% verified publication across all destinations, missing uploads are scheduled at 1–2 videos per day (no mass dumping), and purging requires explicit manual creator approval.

  • Zero Silent / Automatic Deletion: Files are never deleted automatically in the background. Once verified across all platforms, videos enter an "Eligible for Cleanup" staging state requiring explicit creator confirmation.
  • Anti-Mass Upload Throttling (1–2 Videos/Day): Strictly prevents bulk upload flooding. Missing Facebook/Instagram catch-up uploads or folder queues are paced at 1 to 2 videos per day across peak engagement windows.
  • Multi-Platform Verification Gate: Queries YouTube Data API and Meta Graph API to verify live status before marking any file eligible for deletion.
  • Missing Platform Protection & Auto-Catchup: If a video is on YouTube but missing on FB or IG, cleanup is strictly locked and the system auto-schedules paced uploads for the missing platforms.
  • Dedicated Deleted Videos Library: Separate library view in web/library.html listing all deleted/archived videos, complete with connected account names, platform icons, live post URLs, and reclaimed storage statistics.
app/cleaner.py app/scheduler.py web/library.html
